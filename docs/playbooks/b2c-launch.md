# 型 #01 — B2C ローンチ(0 → 1)

> GTMOS の最初の型。**まず人力で 2 回完走し、効いた工程だけを自動化する。**
> 自動化から入らない。効くかどうか分からないものを機械化しても、速く間違えるだけ。

- **適用範囲**:B2C プロダクト(モバイルアプリ / Web アプリ)の 0 → 1 ローンチ。サブスク課金前提。
- **想定期間**:T-90 〜 T+90(準備 3 ヶ月 + launch 後 3 ヶ月)
- **想定体制**:コア 1 名 + 業務委託 + AI パイプライン

## この型の合格条件

| 段階 | 合格ライン |
| --- | --- |
| 1 回目(人力) | 完走し、§6 の全指標が記録されている |
| 2 回目 | **1 回目の 50% 以下の工数**で完走 |
| 型として成立 | コア以外(業務委託)が §2 のチェックリストで回せる |
| 外販可 | 上記に加えて、内部 2 事業で再現済み |

## 1. 勝ち筋(2026 時点の事実)

推測ではなく数値の出ているものだけを置く。数値の確度は 3 段階で明示する。
**◎ = 大規模一次データ / ○ = 業界調査 / △ = 方向性のみ(要自社検証)**

### 1.1 収益構造 — ハードペイウォールが基本形 ◎

RevenueCat の 2026 年レポート(11.5 万アプリ / 160 億ドル / 10 億トランザクション)より:

| | ハードペイウォール | フリーミアム |
| --- | --- | --- |
| Day-35 転換率(中央値) | **10.7%** | 2.1% |
| インストールあたり収益(Day-60) | **$3.09** | $0.38 |
| 1 年後リテンション | 27% | 28% |

**転換率で約 5 倍、収益で約 8 倍の差。しかもリテンションはほぼ同じ。**
「まず無料で使ってもらう」は、B2C サブスクにおいては 2026 年時点で**明確に不利**。

- **既定値をハードペイウォールにする。** フリーミアムにするなら、それを選ぶ理由(バイラルループが課金より価値を生む等)を明文化してから選ぶ。
- 例外:プロダクト自体が招待・共有で伸びる構造(K が高い)の場合のみフリーミアムを検討。ただし §1.7 の通り、その条件を満たす B2C はごく少数。

### 1.2 トライアル — 「短いほど良い」は間違い ◎

| トライアル長 | 転換率(中央値) |
| --- | --- |
| 17〜32 日 | **42.5%** |
| 4 日未満 | 25.5% |

業界は逆に短期化している(4 日以下の採用が 2025 年 42.1% → 2026 年 46.5%)。
**ここは逆張りが効く領域。** 長いトライアルを既定にして、短縮する場合だけ根拠を要求する。

### 1.3 最初の 60 分が全て ◎

- 3 日トライアルの解約のうち **55.4% が Day 0**、**84% が最初の 24 時間以内**。
- つまり解約は「使ってみて合わなかった」ではなく、**「価値に到達する前に離脱した」**。

これが意味するのは、**獲得より前にオンボーディングを設計しないと、広告費が全部漏れる**ということ。
獲得施策の前に「初回起動から 60 分以内に、ユーザーが何を達成していれば勝ちか」を 1 文で定義する。この文が書けないうちは広告を回さない。

### 1.4 AI プロダクト固有の罠 ◎

| | AI アプリ | 非 AI アプリ |
| --- | --- | --- |
| 1 年 LTV | **$30.16** | $21.37 |
| 月額プランの 12 ヶ月リテンション | **36% 悪い** | — |

**「試すためには割高でも払うが、使い続ける理由が見つからない」。**
グループの AI プロダクト(ShogunAI 等)に直接刺さる論点なので、型の中で明示的に扱う。

対処:
1. **年額に寄せる。** 月額の 12 ヶ月リテンションが構造的に悪いなら、年額比率を上げる方が早い。
2. **習慣形成を機能として設計する。** 「毎日開く理由」がプロダクト側にないと、マーケでは埋められない。
3. ただし年額には別の問題がある(次項)。

### 1.5 年額の 1 年目チャーンが悪化している ◎

- 年額の 1 年目総チャーンは **約 72%**(2025 年の約 56% から悪化)
- そのうち **35% が 1 ヶ月目**に発生
- 解約は 1 ヶ月目にスパイク → 中盤 3〜10% で安定 → **12 ヶ月目に再スパイク**

→ 年額購入直後の 30 日間に「買ってよかった」を再確認させる導線を必ず入れる。ここは自動化しやすく、効果が読める工程(§5 の P5)。

**課金失敗も無視できない**:Google Play では解約理由の **31%** が課金失敗(2025 年 28.2% から悪化)。App Store は 14%。
Android は dunning(再請求)最適化で **失われた収益の 15〜20% を回収可能**。地味だが、施策の中で最も費用対効果が読める部類。

### 1.6 クリエイティブは量の勝負 ○

Motion による 55 万広告 / 13 億ドル分の分析:

- Meta 広告で「勝ち」になるのは約 **5%**
- **約 50% はまともに配信されずに終わる**
- クリエイティブは **5〜7 日で更新**、または **CTR がピークから 20% 下落したら差し替え**

**1 本の "ヒーロー動画" に賭ける戦い方は成立しない。** 20 本作って 1 本が当たる前提で、当てるまでの回転数を上げるゲーム。
→ ここが GTMOS の「AI ネイティブ」が最も分かりやすく効く場所。**制作速度そのものが競争力になる唯一のチャネル。**

補足(○〜△):
- マーケターの 60% が「クリエイター制作物はブランド制作物を上回る」と回答。単発キャンペーンより**常時稼働型のクリエイタープログラム**が主流化。
- 消費者の 78% が Reels / TikTok で新商品を知りたいと回答。
- **実際の UI キャプチャ > スタイライズされたコンセプト映像**(demo → signup 転換で上回る)。73% が冒頭が不明瞭だと 15 秒未満で離脱。
  → ローンチ動画は「かっこいい映像」ではなく「触っている画」を主軸にする。前回議論した実写方針(現場・画面を撮る)と一致する。

### 1.7 バイラルは主軸にならない ○

消費者向けプロダクトの K 値(バイラル係数)の現実:

| K 値 | 評価 |
| --- | --- |
| 0.15〜0.25 | 良好 |
| 0.4 | 優秀 |
| 0.7 | 例外的 |
| **> 1 の持続** | ほぼ存在しない(WhatsApp、初期 Zoom 等の数例のみ) |

**紹介は「獲得コストを下げる補助輪」であって、成長エンジンではない。**
K は対象ネットワークが飽和すると必ず減衰する。「バイラルで伸ばす」を計画の前提に置いた時点で計画が壊れる。

実装上の鉄則:
- **報酬をインストールで払わない。** 紹介先が「最初の意味ある行動」を完了してから払う。
- 紹介プログラムが早期に停止される最大の理由は**不正**。設計時点で対策を入れる。
- 有形の報酬は紹介率を **3〜5 倍**にする(ポイントや称号ではなく、実利)。

### 1.8 中央値は死んでいる ◎

- 上位 25% のアプリ:**MRR 前年比 +80%**
- 下位 25% のアプリ:**-33%**
- 中央値:+5.3%

**「そこそこ伸びている」は安全地帯ではない。** 中間層は縮小側に引き込まれる。
型の設計思想として、**平均的な施策の総花的な実施ではなく、勝ち筋への集中**を既定にする。

各項目は「誰が(C=コア / 外=業務委託 / A=AI)」を明示する。これが後の自動化候補リストになる。

- [ ] **A+C** ペイドの小規模テスト **$1,000〜5,000**(Meta / TikTok)

### T-0|ローンチ当日

| **クリエイティブ量産・テスト** | 14 日 | 中 | **高** | **高** |

| **ウェイトリスト + 紹介** | launch 時 | 低 | 中 | **高** |
| **課金失敗リカバリ** | 即 | 低 | **高** | **高** |
| **クリエイター常時プログラム** | 1〜2 ヶ月 | 中 | 中 | 一部 |

**Product Hunt の実態**(○):

→ **やる。ただし半日で終わらせる。** 主軸に据えると期待値を大きく外す。

## 4. 人力 → 自動化の昇格ルール

**自動化は目的ではなく、検証済みの工程を安くする手段。** 順序を守る。

```
Step 1  人力で 1 回やる          → 効くかどうか分からないので測る
Step 2  人力でもう 1 回やる       → 再現するかを見る。ここで落ちる施策が大半
Step 3  手順を書く               → 書けない = まだ型になっていない
Step 4  3 回目を機械化する        → ここで初めて自動化
Step 5  人が残る判断点を明示する   → 全自動にしない。判断は残す
```

### 昇格の条件(全部満たすこと)

1. **2 回以上、人力で実行済み**
2. **効果が数値で確認できている**(効かなかったものを自動化しない)
3. **手順が文書化されている**
4. **入力と出力が定義できる**(定義できない = 判断であって作業ではない)

### 自動化しないもの

- 初期ユーザーとの会話
- コミュニティへの参加
- クリエイティブの**選抜**(生成はする、選ぶのは人)
- 価格の意思決定
- 止める判断

## 5. 自動化候補(Lv2 パイプライン)

前提として、AI 活用は 3 段階で見る。

| | レベル | 中身 | 差別化 |
| --- | --- | --- | --- |
| Lv1 | 制作補助 | コピー生成、リサーチ、要約 | **ゼロ**。全員やっている |
| Lv2 | パイプライン化 | 工程が半自動で流れる | **ここが分岐点** |
| Lv3 | 判断の機械化 | 蓄積データから次の打ち手を出す | 将来 |

以下は **Lv2 の候補を、着手順に並べたもの**。上から潰す。

### P1|リサーチ → 構造化(着手順 1)

- **入力**:カテゴリ、競合 URL 群、ストアレビュー
- **出力**:ICP 仮説 / 競合ポジショニングマップ / 不満クラスタ / 未充足ニーズ
- **人が残る**:仮説の採否
- **なぜ最初か**:毎案件で必ず発生し、毎回ほぼ同じ作業。工数削減が最も読める
- **昇格条件**:2 案件で人力実施済み、出力フォーマットが固定できている

### P2|メッセージング量産 → 選抜(着手順 2)

- **入力**:P1 の出力 + ウェイトリストの絞り込み質問への回答
- **出力**:訴求軸 20 案 → LP コピー / 広告コピーのバリエーション
- **人が残る**:**選抜。ここは絶対に機械に渡さない**
- **効く理由**:量が要る作業で、質のばらつきを人が最後に吸収できる構造

### P3|クリエイティブ量産 → テスト → 疲弊検知(着手順 3・最重要)

- **入力**:P2 の勝ち訴求 + 実写素材 + UI キャプチャ
- **出力**:静止画 / 縦動画のバリエーション、配信設定、テスト設計
- **監視**:CTR ピーク比 **-20%** で自動アラート → 差し替えキューに投入。**5〜7 日サイクル**
- **人が残る**:ブランド適合の最終確認、差し替えの実行判断
- **なぜ最重要か**:勝ちが約 5%・半分は配信されずに終わる世界。**回転数がそのまま成果になる唯一の領域**で、AI ネイティブの効果が数字で証明できる
- **証明のしかた**:1 案件あたりの制作工数が何 % 落ちたかを実測して記録する。**この数字が営業資料で最も強い一枚になる**

### P4|ASO / CPP(着手順 4)

- **入力**:キーワード群、流入元セグメント
- **出力**:CPP 案 3〜5、スクショ 1〜3 枚目のバリエーション、テスト設計
- **人が残る**:キーワード戦略、ブランド表現の最終判断
- **注意**:2 週間データを溜めてから追加。**15〜20 枚超で逓減**

### P5|オンボーディング & ライフサイクル(着手順 5)

- **入力**:イベントログ(起動 / 各ステップ通過 / 60 分到達 / 課金)
- **出力**:離脱地点の特定、トライアル中のメール / プッシュ、年額購入後 30 日のフォロー
- **人が残る**:文面のトーン、送るかどうかの判断
- **効く理由**:解約の 84% が 24 時間以内。**獲得を増やすより、ここを直す方が安い**

### P6|課金失敗リカバリ(dunning)

- **入力**:課金失敗イベント
- **出力**:再請求タイミングの最適化、通知
- **人が残る**:ほぼなし。**最も全自動化しやすい**
- **期待効果**:Android で失われた収益の **15〜20% 回収**。地味だが確実

### P7|週次レポート → 次アクション提案

- **入力**:全チャネルの指標
- **出力**:週次サマリ + 次に打つべき手の候補
- **人が残る**:採否
- **位置づけ**:**Lv3(判断の機械化)への入口**。P1〜P6 のデータが溜まって初めて意味を持つので、最後でいい

## 6. 計測設計と合格ライン

**計測が入っていない状態で広告を回さない。** これは例外なし。

### 必ず取る指標

| 段階 | 指標 | 合格ライン(初期目安) |
| --- | --- | --- |
| 獲得 | 登録単価 | $5〜25(カテゴリによる) |
| 獲得 | オーガニック登録 / 日 | ペイド開始前に **5〜15** |
| **活性** | **60 分以内の勝利条件到達率** | **これが North Star** |
| 活性 | Day 0 解約率 | 低いほど良い。**ここが全て** |
| 課金 | Day-35 転換率 | ハードペイウォールなら **10% 前後**が中央値 |
| 課金 | インストールあたり収益(D60) | ハードペイウォールなら **$3 前後**が中央値 |
| 継続 | 1 年リテンション | **27〜28%** が中央値 |
| 継続 | 年額 1 ヶ月目チャーン | 年額解約の 35% がここ。**下げれば直接効く** |
| 効率 | 課金失敗による解約比率 | Android **31%** / iOS **14%** が中央値 |
| クリエイティブ | 勝ち率 | 約 **5%** 前提。下回るなら本数が足りない |

### 型としての指標(事業側)

売上ではなく**資産の増分**を見る。

- 今週、型に何が追加されたか
- 再利用率(新規案件のうち既存アセットで賄えた割合)
- Lv2 に到達したパイプラインの数(目標:主要 5 工程のうち 3 つ)
- 1 案件あたりの人的工数(**低下し続けているか**が唯一の合格条件)

## 7. やらないこと

- **フリーミアムを既定にする** — 理由を書けない限り選ばない(§1.1)
- **計測前に広告を回す** — 漏れているバケツに水を注ぐ行為
- **オンボーディングを直す前に獲得を増やす** — 同上
- **Product Hunt を主軸にする** — 半日で終わらせる副次施策(§3)
- **バイラルを成長計画の前提にする** — K > 1 は持続しない(§1.7)
- **1 本のヒーロー動画に賭ける** — 勝ちは約 5%(§1.6)
- **効果未検証の工程を自動化する** — 速く間違えるだけ(§4)
- **クリエイティブの選抜を機械に渡す** — 生成は渡す、選抜は渡さない
- **オーガニック短尺を launch 直前に始める** — 効き始めは 3〜6 ヶ月後(§3)

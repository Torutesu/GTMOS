# Superdemovideo — 動画の作法(外部リサーチの取り込み)

出典: [The Launch Video Company のブログ](https://www.launchvideo.com/blog)(2026-07 時点)

このドキュメントの目的は「参考になった話」を並べることではない。
**テンプレート(`templates/launch/*`)とハーネス(`scripts/accept.ts`)に落ちる形に翻訳すること**が目的。
だから各項目は必ず次の 3 列を持つ:

| 主張(出典) | 我々の実装上の意味 | どこで強制するか |

強制先は 3 種類しかない:

- **T** = テンプレート(`skeleton.json` / `theme.json`)— データで表現でき、テンプレごとに変えられる
- **H** = ハーネス(`accept.ts` / unit テスト)— 機械が検査して落とせる
- **D** = 判断(このドキュメント + プロンプト)— 数値化できず、人と LLM が守る

D は最小にする。D にしか置けないものは、いずれ H に昇格させる候補として印を付ける。

---

## 1. フック(最初の 1.7 秒)

| 主張 | 実装上の意味 | 強制 |
| --- | --- | --- |
| 視聴者は約 **1.7 秒**で「見る/スクロールする」を決める | イントロは 1.7 秒より前に終わり、**その時点で製品が動いている**こと | **T** `skeleton.hookMs: 1700` / `intro.durationMs: 1600` |
| 弱いフックは 3 秒で最大 **80%** を失う。最初の 3 秒が成否の約 8 割 | タイトルカード・ロゴ・ブランドアニメは禁止 | **T**(intro は最初の実画面の上に重ねる設計)+ **H**(下記) |
| 1 フレーム目がサムネイルになる | poster は「製品が写っている最初のフレーム」。ロゴ不可 | 実装済(`compose.ts` が t=0.8s のフレームを poster に採用) |
| 冒頭に人が写ると維持率が **2 倍** | M1 の対象外(実写を持たない)。M2 の「founder カット合成」で回収する | **D** |

**H に昇格させたい検査(未実装・次の一手):**
`hookMs` 時点のフレームを取り出し、`nonBackgroundRatio()`(seed で既にある)で
「背景色でない画素が一定割合以上」を assert する。これで
「1.7 秒時点でまだ無地のプレートを映している」テンプレートは CI で落ちる。

## 2. 尺

| 主張 | 実装上の意味 | 強制 |
| --- | --- | --- |
| ヒーローは **90 秒前後**(190–225 words) | `targetDurationMs: 60000` / `maxDurationMs: 70000` は 90 秒より内側。安全側 | **T** |
| **90 秒を超えると 10 秒ごとに完走率が約 12% 落ちる** | 90 秒は上限であって目標ではない。ステップが増えたら**尺を伸ばさず hold を詰める** | **T** + 実装済(`compressHolds` は hold を縮めるだけで step を落とさない) |
| 15 秒カット(35–40 words)、6 秒カット | M1 は未実装。1 キャプチャから短尺を切り出すのは**タイムラインの再構成だけ**で作れる | **D**(M2 要件) |

`compressHolds` が「step を落とさず hold を詰める」設計であることは、
この主張と一致している ─ 尺を守るために手順を省くと、デモが嘘になる。

## 3. 縦・横・正方形(masters)

| 主張 | 実装上の意味 | 強制 |
| --- | --- | --- |
| 9:16 は X の Immersive Media Viewer 経由で**最大 7 倍**のエンゲージメント | 9:16 は「おまけ」ではなく主戦力 | **T** `formats[].video_916` |
| 1:1 はモバイルタイムラインで強い | **1:1 を追加した**(本リサーチで実際に増やした format) | **T** `formats[].video_11` |
| 16:9 はデスクトップ寄りのデモ用 | ヒーロー/LP 埋め込み用として維持 | **T** |
| 最低 **3〜5 本**のバリアントを出す | 3 本(16:9 / 9:16 / 1:1)は最低ライン。短尺 2 本で 5 本になる | **H** `accept.ts` #7 が 3 本すべてを ffprobe で検査 |
| テキストは縦フレームの**中央 50%**に収める(プラットフォーム UI が上下を覆う) | フォーマットごとに字幕の安全域を持たせる | **T** `formats[].safeBottomRatio`(9:16 = 0.24、1:1 = 0.12)+ 実装済(`render.ts`) |

## 4. 音なし前提

| 主張 | 実装上の意味 | 強制 |
| --- | --- | --- |
| モバイル再生の最大 **85%** はミュート。オンライン動画の **75%+** がモバイル | 字幕は装飾ではなく**維持率そのもの**。BGM もナレーションも前提にしない | 実装済(M1 は無音・字幕焼き込み) |
| 焼き込み字幕 **と** プラットフォーム字幕の両方 | 焼き込み(英語)+ `.srt`(en/ja)を両方出す | **H** `accept.ts` #9 |
| 高コントラスト・モバイルサイズ | `theme.caption` は不透明度 0.82 の暗背景 + 白文字 | **T** |

日本語は焼き込まず `.srt` のみ、という判断は変えていない
(CJK フォントの有無で描画が壊れるリスクを本番経路に入れない)。

## 5. CTA

| 主張 | 実装上の意味 | 強制 |
| --- | --- | --- |
| CTA は **1 本だけ**。終盤に常時表示 | `cta` は 1 件しか持たない構造(`{label, url}`)。複数持てないことが仕様 | 実装済(`emit.ts` / player) |
| 画面上の CTA と投稿本文の文言を一致させる | 将来 X 投稿文を生成するとき、CTA 文字列を単一の出所から引く | **D**(M2) |

## 6. 計測(M1 では持たないが、設計を先に決めておく)

| 主張 | 我々の指標 |
| --- | --- |
| hook rate 35–45%+ | 公開デモの 1.7 秒到達率 |
| skip rate < 30% | 3 秒離脱率 |
| 平均視聴 = 尺の 50%+ | ─ |
| 動画つき LP は 4.8% vs 2.9% | **freshness バッジのクリック → デモ到達**を我々の一次指標にする |

**重要な含意:** 「views ではなく conversion で測る」という主張は、
Superdemovideo の価値提案そのものと一致する。
我々が売っているのは動画ではなく**常に正しい動画**であり、
その差が出るのは view ではなく「デモを見た人が実際に触る率」の側だから。

## 7. 配信(プロダクトの外側だが、テンプレの前提になる)

- **ネイティブアップロード必須**(リンク投稿は抑制される)→ 出力は「貼れるファイル」であって「URL」ではない。M1 が mp4 を artifact として落としているのは正しい。
- 最初の 1 時間が勝負、**約 6 時間で可視性が半減**する → 再生成の価値は「いつでも最新」ではなく「**launch の朝に最新**」。regen をワンコマンドで終わらせている理由がここにある。
- 5〜10 アカウントに 1 分以内でコメントさせる、90 分は返信を見る → GTM 側の運用。`docs/playbooks/b2c-launch.md` と `docs/cases/shogunai-launch.md` に属する話で、プロダクトには入れない。

## この調査で実際に変えたもの

1. `templates/launch/skeleton.json` に **1:1(1080×1080)フォーマットを追加**。masters が 2 本から 3 本になった。
2. フォーマットごとの **`safeBottomRatio` / `captionSizeRatio`** を追加し、`render.ts` がそれを見るようにした。9:16 の字幕はもう下端に貼り付かない。
3. ウォーターマークも同じ安全域の上に移した(字幕を覆わない/UI に覆われない)。
4. `skeleton.hookMs: 1700` を明示し、intro の 1.6 秒という値の**根拠**をコメントに書いた。以前は「短いほうがいい」という感覚値だった。
5. `scripts/accept.ts` #7 が 3 本すべてを ffprobe で検査するようにした。

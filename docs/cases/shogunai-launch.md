## 1. 構造判定:この課金設計は型 #01 の推奨と一致している

**7 日トライアル + 無料枠なし = ハードペイウォール型。** 型 #01 §1.1 の推奨そのものです。

- ハードペイウォールの Day-35 転換率は中央値 **10.7%**(フリーミアムは 2.1%)
- インストールあたり収益(D60)は **$3.09**(フリーミアムは $0.38)

**一番大きい構造判断は既に正しい側にあります。** ここは動かす必要がない。

唯一、ベンチマークから外れるのは**トライアルの長さ**だけです。

| トライアル長 | 転換率(中央値) |
| --- | --- |
| 17〜32 日 | 42.5% |
| **7 日(該当)** | **中間帯。目安 30〜35%** |
| 4 日未満 | 25.5% |

長さは固定なので、**この差はオンボーディングとトライアル中の設計で埋める**。以下はその前提で組んでいます。
「17〜32 日の方が転換率が高い」という事実だけ記録しておき、将来 A/B の余地が生まれたときの検証候補として残します(今は動かさない)。

## 2. SHOGUN 固有の最大の問題:**Day 0 のメモリは空**

これが全ての中心です。ここを外すと他を全部やっても転換しません。

SHOGUN の価値は**蓄積された記憶**から生まれます。ところがトライアル初日、記憶はゼロです。
つまり **プロダクトが最も価値の低い瞬間に、ユーザーは 7 日の判断を始める**。

型 #01 §1.3 の数値がここに重なります:

- 3 日トライアルの解約の **55.4% が Day 0**、**84% が最初の 24 時間以内**
- 解約は「使ってみて合わなかった」ではなく **「価値に到達する前に離脱した」**

さらに §1.4:AI アプリは 1 年 LTV が 41% 高い($30.16 vs $21.37)一方で、**月額プランの 12 ヶ月リテンションは 36% 悪い**。
「試すためには払うが、使い続ける理由が見つからない」——SHOGUN が正面から食らう構造です。

### 打ち手は 3 つ

**① Execution を先に見せ、Memory を後から効かせる**

Execution Layer は**記憶ゼロでも初日から動く**。Memory Layer は動かない。
だから初日の主役は Execution。「入れた 10 分後に、何かを実際にやってくれた」を作る。
Memory はバックグラウンドで溜めておき、**Day 2 以降に回収する**(次項)。

**② Day 0 でメモリを人工的に埋める**

初回起動時に、既存データを取り込んで「初日なのに 1 ヶ月分の記憶がある」状態を作る。
候補:カレンダー / 既存のノート / ブラウザ履歴 / Kioku の既存ユーザーデータ。
**この 1 機能が、7 日という制約下では最も転換率に効く可能性が高い。** プロダクト側の投資判断として最優先で検討する価値があります。

**③ 勝利条件を 1 文で固定する**

型 #01 の必須項目。SHOGUN の場合の暫定案:

> **初回起動から 60 分以内に、SHOGUN が「ユーザーがまだ頼んでいないこと」を 1 つ実行し終えている。**

この 1 文が決まらないうちは広告を回さない。

## 3. 7 日トライアルの日次設計

| Day | ユーザー側で起きるべきこと | 打ち手 |
| --- | --- | --- |
| **Day 0** | **60 分以内に Execution が 1 回成功する** | 初回起動でデータ取り込み → 権限付与 → 初回実行までを一本道に。分岐を作らない |
| Day 0 夜 | 「今日の分」が記憶に入ったことを見せる | 初日の Morning Brief 相当を**夜に 1 回**先出しする |
| **Day 1** | **朝、Morning Brief で「昨日の自分」が返ってくる** | ここが Memory Layer の初回ペイオフ。**Day 1 の朝を逃すと 84% ゾーンに入る** |
| Day 2〜3 | 記憶が積み上がる実感 | 「3 日分の記憶ができました」を可視化。積み上がりそのものを見せる |
| **Day 4** | **中間地点。使っていない人を検知** | 未起動 / 未実行のセグメントに個別対応。ここが最後の救出チャンス |
| **Day 5** | **年額の提示**(§4) | 「あと 2 日」ではなく「ここまでの記憶が消えます」で伝える |
| Day 6 | 失うものの可視化 | 蓄積された記憶量を数値で見せる。**離脱コストを実体化させる** |
| **Day 7** | 課金 | 決済失敗のリカバリを事前に仕込む(§4) |

**Day 1 の朝が最大の山**です。Day 0 の 60 分と Day 1 の Morning Brief、この 2 点に資源を集中する。

## 4. 課金設計

### 年額に寄せる

- 月額 $62 / 年額 $49(月あたり)。**年額は 21% 安い**
- §1.4 の通り、AI アプリは**月額の 12 ヶ月リテンションが構造的に 36% 悪い**
- → **Day 5 の提示は年額を主、月額を副にする**

### ただし年額には別の罠がある

- 年額の 1 年目総チャーンは約 **72%**(前年の約 56% から悪化)
- そのうち **35% が 1 ヶ月目**

→ **年額購入後 30 日のフォローを必ず入れる。** 「買ってよかった」を再確認させる導線。
自動化しやすく効果が読めるので、パイプライン P5 の最優先項目にする。

### 決済失敗

- macOS / App Store 経由なら解約理由の **14%**、Google Play なら **31%** が課金失敗
- Android 展開時は dunning 最適化で**失った収益の 15〜20% を回収可能**
- SHOGUN は macOS 単独なので優先度は下がるが、**Stripe 直販なら別途仕込む**

## 5. X 運用

### 5.1 なぜ X が主戦場として正しいか

ターゲットが **AI-native individual(founder / builder / researcher)** で、プロダクトが macOS ネイティブ・BYOK・MCP・local-first。
**この層が実際に居るのは X だけ**です。TikTok や Reels は該当しません。型 #01 のチャネルカタログをそのまま当てるのではなく、ここは X に集中させます。

加えて、X は**創業者個人の言葉が製品の信用に直結する**数少ない場所です。体制がコア 1 名であることが、ここでは弱点ではなく武器になります。

### 5.2 2026 年の X の物理法則(先に押さえる)

運用設計はアルゴリズムの制約から逆算します。**確度:○(業界分析。X の公開ランキング重みに由来するものを含む)**

| 事実 | 運用上の帰結 |
| --- | --- |
| **リプライはいいねの 27 倍の重み** | 「投稿する」より**「会話を起こす」**方が伸びる。運用の中心はリプライ |
| **外部リンクは到達 50〜90% 減** | **本文にリンクを貼らない。** syogun.com は必ず**最初のリプライ**に置く |
| **非 Premium + リンクはほぼ到達ゼロ**(2026年3月以降) | **X Premium は必須コスト。** 加入で到達 2〜4 倍 |
| **最初の 30 分の反応速度が全て**。10 件超で増幅が起動 | 投稿直後 30 分は張り付く。**投げっぱなしにしない** |
| **クリエイター多様性上限** — 1 人のフォロワーの For You に出る自分の投稿数に日次上限 | **投稿を増やすと薄まる。** オリジナルは 1 日 1〜2 本に絞る |
| **ネイティブ動画(60 秒未満)が最も伸びる** | 外部リンクの YouTube ではなく **X に直接アップ** |

**最後の 2 つが重要です。**「たくさん投稿する」は 2026 年の X では逆効果。**本数ではなく、1 本の初速と、リプライの量**で勝つゲームになっています。

### 5.3 投稿設計

角度は既存の `shogun-angle-tweet` スキルに定義済みの 5 つをそのまま使います。**新しく作らない。**

| 角度 | 中身 | 週の配分 |
| --- | --- | --- |
| **E. Build-in-public** | 実装ディテールから思想を滲ませる | **週 3**(最も安定して伸びる) |
| **B. Observation** | 技術トレンド → 「だから何が起きる」 | 週 2 |
| **A. Position** | 競合ニュースに対する立ち位置宣言 | 週 1〜2(ネタ次第) |
| **C. Counter** | 前提をひっくり返す | 週 1 |
| **D. Category creation** | 新しいラベルを貼る | 隔週 1 |

### 形式の配分(週 7〜10 本)

- **ネイティブ動画 週 3 本**(各 60 秒未満)— **実際に SHOGUN を触っている画面録画**
  型 #01 §1.6 の通り、実 UI キャプチャはスタイライズされたコンセプト映像より demo → signup 転換で上回る。
  かつ冒頭が不明瞭だと 73% が 15 秒未満で離脱するので、**最初の 3 秒で何が起きるかを見せる**。
- **テキストのみ 週 4〜5 本** — Observation / Counter / Position
- **画像 1 枚 週 1〜2 本** — アーキテクチャ図、記憶の可視化

### 鉄則

- リンクは本文に入れない。**必ず 1st reply**
- ハッシュタグなし、メンションなし、絵文字なし(⚔ は launch 告知のみ)
- 「かもしれない」を書かない。断定する
- NG コピー:`AI-powered` / `revolutionary` / `your second brain` / `privacy-first` 単独

### 5.4 リプライ戦略(ここが本体)

リプライがいいねの 27 倍の重みを持つ以上、**運用工数の過半をリプライに置く**のが合理的です。

**固定ターゲットリストを作る(30〜50 アカウント)**

1. 競合の周辺 — Littlebird / Limitless / Screenpipe / Granola / Conway / Nia の投稿と、**その下で不満を書いている人**
2. 技術の周辺 — MCP、Accessibility API、local-first、memory / RAG、Managed Agents
3. 該当層 — macOS で作っている個人開発者、AI ツールを毎日試している人

**1 日 20〜30 リプライ。** ただし:

- **一言の同意はしない。** 「Agreed」「This」は 27 倍の重みを取りに行けない。会話が続かない
- 自分の経験か、実装の具体を必ず入れる。SHOGUN を毎回宣伝しない(**5 回に 1 回でいい**)
- **自動リプライは使わない。** 会話の質が重みの源泉なので、自動化した瞬間に効果が消える

### 5.5 ローンチ週

- ローンチ投稿は**ネイティブ動画 60 秒**。リンクは 1st reply
- 投稿後 30 分は他のことをしない。**初速が全てを決める**
- ⚔ を使うならここだけ
- **Product Hunt は同日にやるが、半日で終わらせる**(型 #01 §3:10 位圏外は 500 訪問未満、創業者の 89% が「もう一度はやらない」と回答)
- Build-in-public 型のローンチで見込める初日登録は **300〜800**(△ 方向性のみ。自社実測に置き換える)

### 5.6 やらないこと

- **本文にリンクを貼る**(到達 50〜90% 減)
- **非 Premium で運用する**(リンク付き投稿がほぼ到達ゼロ)
- **1 日 5 本以上のオリジナル投稿**(多様性上限で薄まる)
- **エンゲージメントポッド / 相互いいね**(質が重みの源泉なので逆効果、かつリスク)
- **自動リプライ / 自動 DM**
- **スレッドの乱用**(伸びる時は伸びるが、単発の会話起点より安定しない)
- **投稿して離席**(最初の 30 分を捨てるのは最ももったいない)

## 6. 計測

X はリンクをリプライに逃がす以上、**クリック計測が構造的に壊れます**。前提として設計する。

### 連結して見る

```
X 指標           → プロフィール訪問 → LP 到達 → 登録 → Day0 60分到達 → Day7 課金 → 年額比率
(リプライ数)       (X Analytics)      (UTM)     (自社)   (★ North Star)   (★)        (★)
```

### 自己申告アトリビューションを必ず入れる

オンボーディングに **「SHOGUN をどこで知りましたか」** を 1 問入れる。
リンク計測が壊れている以上、**これが唯一の実用的な帰属データ**になります。X の運用が効いているかどうかは、ほぼこの 1 問で判断することになる。

### 記録する数値(型 #01 §6 に自社実測を書き戻す)

| 指標 | 目安 / 位置づけ |
| --- | --- |

## 7. 人力 → 自動化

型 #01 §4 の昇格ルール(人力 2 回 → 手順化 → 3 回目で機械化)をそのまま適用。

### 既に資産があるもの

**`shogun-angle-tweet` スキルは既に Lv1 として動いています。** インプットを渡すと角度抽出 + EN/JA ツイートが出る。
これを **Lv2 に上げる**のが、X 運用における最初の自動化です。

```
現状 Lv1:  人がネタを見つける → スキルに渡す → 出力を人が投稿

Lv2 化:    ① ネタ収集を自動化(競合 6 社 + 技術トピックの監視)
              ↓
           ② 有望なインプットだけをスキルに自動投入
              ↓
           ③ 下書きキューに溜める(EN/JA 両方)
              ↓
           ④ 人は「選ぶ・直す・投稿する」だけ ← ここは渡さない
```

**②③ が自動化対象、④ は人に残す。** 選抜を機械に渡した瞬間にトーンが崩れます(型 #01 §4「自動化しないもの」)。

### 自動化しない(X 運用)

- **リプライ**(27 倍の重みの源泉が会話の質なので、自動化は自傷行為)
- 投稿の最終選抜
- 初期ユーザーとの会話
- 投稿後 30 分の張り付き

### 自動化の順序

| 順 | 対象 | 昇格条件 |
| --- | --- | --- |
| 1 | ネタ収集 → 下書きキュー | 人力で 2 週間運用済み |
| 2 | 投稿指標の日次集計 | — |
| 3 | 動画クリップの書き出し(画面録画 → 60 秒 / 縦横) | 人力で 6 本作った後 |
| 4 | Day 0〜7 のライフサイクル配信(P5) | 日次設計が実測で固まった後 |
| 5 | 年額購入後 30 日フォロー | 同上 |

## 8. 最初の 30 日(X ランプ)

**ローンチ前に助走をつける。** オーガニックは立ち上がりに時間がかかるので、launch 当日に始めても遅い。

| 週 | やること | 出るもの |

| **W1** | X Premium 加入。ターゲット 30〜50 アカウントのリスト作成。**リプライのみ 1 日 20 件、投稿ゼロ** | 顔を覚えられる |
| **W2** | オリジナル投稿を 1 日 1 本開始(Build-in-public 中心)。リプライ継続 | どの角度が伸びるかのデータ |

**W1 で投稿をゼロにするのが要点です。** 誰にも知られていない状態で投稿しても初速 10 件に届かず、増幅が起動しません。先にリプライで存在を作る。

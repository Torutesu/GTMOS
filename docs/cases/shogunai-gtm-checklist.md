## 1. Track P — プロダクト(GTM がここでブロックされる)

GTM 側では解決できない依存。**早く出して早く判断してもらう。**

### 1-1. 勝利条件の定義 ★★★

- [ ] `[C]` 勝利条件を 1 文で確定
      **暫定案**:「初回起動から 60 分以内に、SHOGUN が"ユーザーがまだ頼んでいないこと"を 1 つ実行し終えている」
      **DoD**:文が確定し、`[P]` がその達成をイベントとして送出できると合意している
- [ ] `[P]` そのイベントを実装
      **DoD**:`activation_win` が発火し、ダッシュボードで到達率が見える

### 1-2. macOS 権限許諾 ★★★ — **最大の未知数**

Accessibility API を使う以上、ユーザーは **System Settings を自分で開いてトグルを入れる**必要がある。
**Day 0 の 60 分の中で最大の離脱点は、価値提案ではなくこの画面である可能性が高い。**
ここが 50% 落ちているなら、広告もコピーも X 運用も全部意味を失う。**最初に測る。**

- [ ] `[P]` 権限フローを段階分解してイベントを打つ
      `権限画面到達 → System Settings 起動 → 許諾完了 → アプリ復帰 → 初回実行`
      **DoD**:各ステップの通過率が個別に見える
- [ ] `[C]` 実測を取り、離脱地点を特定
      **DoD**:どのステップで何 % 落ちているかが数値で言える
- [ ] `[P]` 離脱地点に対する改善(誘導動画 / GIF / 手順の分解 / 復帰検知)
      **DoD**:改善前後で通過率を比較した記録がある
- [ ] `[P]` Automation 権限(MCP が他アプリを操作する場合)も同様に分解
- [ ] `[C]` **この数値が出るまで、有料獲得を開始しない**

### 1-3. Day 0 メモリ初期化 ★★★ — 要判断

初日のメモリが空だと、プロダクトが最も価値の低い瞬間に 7 日の判断が始まる。

- [ ] `[C]` **やるか / やらないかを決める**
      **DoD**:決定と理由が書かれている
- [ ] `[P]` やる場合:取り込み元を決める(カレンダー / 既存ノート / ブラウザ履歴 / **Kioku 既存ユーザーのデータ**)
      **DoD**:初回起動時に「初日なのに N 日分の記憶がある」状態が作れる
- [ ] `[P]` 取り込み量をユーザーに可視化する
      **DoD**:「◯◯件の記憶を取り込みました」が初回起動時に見える

### 1-4. Day 1 の Morning Brief ★★★

Memory Layer の初回ペイオフ。**ここを逃すと 84% ゾーンに入る。**

- [ ] `[P]` トライアル Day 1 の朝に必ず届く導線
      **DoD**:Day 0 に登録した全ユーザーの Day 1 朝の到達率が測れる
- [ ] `[P]` Day 0 の夜に「初日の分」を先出しする
      **DoD**:初日中に 1 回、記憶が入ったことを体感できる
- [ ] `[C]` Brief の中身が「昨日の自分が返ってくる」体験になっているかレビュー

### 1-5. 配布 ★★

- [ ] `[P]` Developer ID 署名 + Notarization
      **DoD**:Gatekeeper の警告なしで起動する
- [ ] `[P]` 自動更新(Sparkle 等)
      **DoD**:ローンチ後の緊急修正が配布できる
- [ ] `[P]` アンインストール導線
      **DoD**:解約したユーザーが綺麗に消せる(評判に効く)

## 10. 止める基準(先に決めておく)

判断が必要になった時には、もう冷静に決められない。**先に線を引く。**

- [ ] `[C]` **権限許諾の通過率が ◯% を下回ったら**、獲得を全停止して §1-2 に戻る
- [ ] `[C]` **60 分到達率が ◯% を下回ったら**、広告を止めてオンボーディングを直す
- [ ] `[C]` **Day 0 解約率が ◯% を超えたら**、Day 0 の体験を作り直す
- [ ] `[C]` **登録単価が $◯ を超えたら**、有料を止めて X オーガニックに戻す

**◯ の値は、最初の 2 週間の実測が出てから埋める。** 今は空欄でいいが、**空欄のまま launch しない。**
